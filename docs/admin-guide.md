# 觅码管理台操作说明

## 登录日志

**入口**：左侧菜单「登录日志」（`/admin/login-events`）；菜单徽章显示今日失败登录数（>0 红标）。

**能看什么**：全部 GitHub 登录/登出事件（成功与失败）、时间、login、事件类型、成败、ip_hash（截断展示）。

**能做什么**：按登录名模糊、成败、事件类型、日期范围（UTC 日，含首尾当日）过滤；行内「反查」输入完整 IP 查同 IP 全部行为（每次反查留审计记录）。失败行保留 180 天（夜间聚合任务顺带清理），成功行永久保留。

**常见操作**：调查异常登录 = 过滤「失败」+ 缩日期；确认某 IP 行为 = 任一行「反查」。

## 全局搜索

**入口**：顶栏搜索框（任意页可用），回车进 `/admin/search?q=`。

**能看什么**：用户（login/简介）、仓库（仓名/标题/简介，走全文索引）、评论（正文，已删除不入搜）三组结果，每组最多 5 条 + 命中计数（超过 1000 显示「1000+」）。

**能做什么**：点「查看全部 →」进对应列表页继续过滤；搜索词 2–50 字，支持中文子串。

## 反馈收件箱

**入口**：左侧菜单「反馈收件箱」（`/admin/feedback`）；菜单徽章显示待处理数（>0 红标）。

**能看什么**：主站用户提交的反馈（问题反馈 / 建议 / 其他），含提交人、正文（列表截断显示，全文见详情页）、状态、已回复条数与时间。列表不展示联系方式，仅详情页可见（隐私）。

**能做什么**：按内容关键词、状态、分类筛选；点「查看」进详情页，在那里改状态（待处理 / 已处理 / 已忽略，三态可任意互转）、写内部备注（仅管理员可见，用户侧永不返回）、发送回复（可多轮，回复不改状态）。每次状态变更、备注保存与回复发送都会写入审计日志。

**常见操作**：每天开工先看红色徽章数 = 待处理总数；处理完把状态改为「已处理」并写一句内部备注留档；需要用户跟进时用「回复」而不是内部备注。

## LLM 用量

**入口**：左侧菜单「LLM 用量」（`/admin/llm-usage`）。

**能看什么**：区间调用数、tokens 合计、失败率、平均耗时四张汇总卡；按日「调用数（柱）+ tokens（线）」双轴图；模型分布列表；消耗最大的 10 个仓库。概览页另有「本月 LLM 调用」小卡（当月调用数 + tokens 合计）。

**怎么用**：右上按钮组切「近 7 日 / 近 30 日 / 近 90 日」（UTC 日界，缺省近 7 日）。数据为纯观测记账：每次模型调用落一行明细（失败调用也计数，失败率 = 失败 ÷ 调用；tokens 以模型服务方上报为准，未上报的调用记 0），明细不保存任何提示词与回复文本。

**加载与失败**：切换区间时立即清除旧结果；加载中或请求失败时，汇总显示「—」，表格显示对应状态。只有成功取得空数据后，调用数与 tokens 才显示 0；加载失败可切换区间重试。

**记账范围**：Web 调用、定时爬取、补筛和评论审核重试均记账。记账采用尽力写入：数据库写锁竞争或写入失败时跳过该条并记录错误，避免等待写锁拖慢模型调用，因此极端竞争时统计可能低估。

**注意**：本页只读；数据自上线起累计、不设保留期。仓库 Top 表仅统计带本地仓库 ID 的调用（补筛、评论审核）；入库前调用不计入仓库榜。「仓库 #N」表示关联仓库记录已不存在、无法获取仓库名。
