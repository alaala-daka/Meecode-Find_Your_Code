# 觅码 · 安全基线（抗渗透加固）设计文档

日期：2026-09-21 · 状态：待审批 · 需求来源：`新一轮完善.txt` 第 1 项（安全防护，增强网站抗渗透打击能力）；基于 `2026-08-31-觅码-信息流全链路-design.md` 与 `2026-08-29-觅码-线上部署-design.md` 的评审结论

## 1. 背景与目标

站点已上线（meecode.tech），采集管道接入真实服务前，现有实现存在四类可被利用的面：

1. **无限流**：`POST /api/ai-draft`、`/api/repos/root`、`/api/expand`、`/api/nodes/detail`、`/api/reader/chat` 每次调用都烧 LLM 配额；解读域会话只需 `POST /api/sessions` 白拿的 session_id，匿名即可驱动。`/api/feed`、`/api/search`、`/api/repos/{id}` 匿名即可驱动写库（曝光/浏览自增，feed.py:23、repos.py:51）。
2. **无安全响应头**：nginx 与后端均无 CSP / HSTS / X-Frame-Options / X-Content-Type-Options / Referrer-Policy，也无请求体大小限制（deploy/nginx-meecode.conf 全文 45 行）。
3. **CSRF 仅剩 SameSite=Lax 一层**：全部写操作无 token、无 Origin 校验。Lax 已挡跨站 POST，但补一层 Origin 白名单校验近乎零成本。
4. **CI 无门禁**：`.github/workflows/deploy.yml` 只构建+部署，不跑 pytest / vitest / tsc —— 破门而入的最短路径是推一个能过的烂提交。

**目标**：以最小改动补齐四层基线 —— nginx 安全响应头与请求体限制、后端应用级限流（护 LLM 计费端点与写端点）、Origin 白名单 CSRF 校验、CI 测试门禁。外加一项顺手项：`index.html` 基础分享 meta（OG/Twitter/canonical）。全部改动的共同原则：**零新依赖、可回滚、不影响离线开发与现有 196 个后端 / 205 个前端测试**。

**非目标（YAGNI）**：
- 验证码（评论区/反馈渠道上线带来真实 UGC 后再按需评估，属第二批次）；
- 依赖 hash 锁定（backend `requirements.txt` 全 `>=` 是既有状态，锁版本涉及供应链策略，单独评估，不在本批）；
- 会话吊销/refresh（登录态是无状态 HMAC cookie，改造需服务端会话存储，属独立子项）；
- WAF / fail2ban / 入侵检测；
- 双提交 CSRF token、自定义请求头校验（Origin 白名单已覆盖威胁模型）；
- 管理后台与管理员鉴权（第三批次，随管理端 spec 设计）；
- 评论区内容 sanitize（随评论区 spec 做，本批不碰 UGC 存储）。

## 3. 决策记录表

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 限流算法与依赖 | stdlib 内存滑动窗口（每键时间戳列表），不引 slowapi/redis。单 worker 部署（systemd 单元即 1 个 uvicorn worker，解读域内存会话本就强制单 worker），进程内计数足够；多 worker 时间隔失效这一限制写入风险表 |
| 2 | 限流键 | 登录用户优先（HMAC cookie 解析出 user_id，不查库，纯计算），匿名回退客户端 IP。IP 取 `X-Forwarded-For` **最后一段**（nginx `$proxy_add_x_forwarded_for` 由受信代理追加，末段即真实客户端；前置段可伪造，弃用） |
| 3 | 限流粒度 | 按端点分桶（llm/session/submit/interact/browse/auth/delist/default），每桶每 60s 一阈值，config.py 集中可调。LLM 桶最严（按钱定价），浏览桶最宽（只防写库放大） |
| 4 | 超限响应 | 429 + `Retry-After` 秒数 + JSON detail；中间件层序保证 429 也带 CORS 头（见 §4.2） |
| 5 | CSP 策略 | 直接执行（非 Report-Only）：`default-src 'self'`，`img-src 'self' data: https:`（README 图片任意域 + 前端 SVG 封面模板），`style-src 'self' 'unsafe-inline'`（React 内联 style 与 markdown 渲染），`script-src 'self'`，`connect-src 'self'`，`frame-ancestors 'none'`。回滚即删头。SEO 批次若加 JSON-LD 内联脚本需同步调 script-src（spec 内标注） |
| 6 | CSRF 方案 | Origin 白名单校验（复用 `CORS_ORIGINS`），仅查非安全方法（POST/PUT/PATCH/DELETE）的 `/api` 路径；无 Origin 头放行（curl/TestClient/非浏览器客户端）；不上双提交 token |
| 7 | CI 门禁形态 | 独立 `test` job（backend pytest + frontend typecheck + vitest），`deploy` 声明 `needs: test`。pytest 步骤显式注入 `LLM_MOCK=true GITHUB_MOCK=true`（CI 无 `.env`，config 默认 mock=false，且 `ensure_prod_secrets` 会拒启） |
| 8 | nginx 上线方式 | conf 在仓库内但**不自动同步服务器**（CI 只 rsync dist + git pull + 重启 backend）。安全头上线 = runbook 手动步骤（nginx -t + reload），写入手册 |
| 9 | 顺手 meta 范围 | 仅首页静态 meta（OG/Twitter/canonical），og:image 暂用 `/icon-512.png`； robots/sitemap/JSON-LD/预渲染留待 SEO 批次 |

## 4. 详细设计

### 4.1 限流中间件（`backend/app/security.py`）

**端点分桶规则**（规则 = 可选方法过滤 + 路径前缀，按序首个命中；未命中落 `default`）：

| 桶 | 路径 | 阈值（次/60s/键） | 理由 |
|----|------|------|------|
| `llm` | `/api/ai-draft`、`/api/repos/root`、`/api/expand`、`/api/nodes/detail`、`/api/reader/chat` | 20 | 每次调用烧钱；ai-draft 已需登录，解读域四端点靠 IP 挡匿名 |
| `session` | `/api/sessions` | 30 | 白拿 session_id 是匿名打 LLM 的前置步 |
| `submit` | `/api/submit` | 5 | 投稿触发 GitHub 拉取 + LLM 精筛 |
| `interact` | `/api/interactions` | 60 | 幂等写，阈值防刷 |
| `browse` | `GET /api/feed`、`GET /api/search`、`GET /api/repos/` | 240 | 匿名写库放大面，宽阈值只挡异常 |
| `auth` | `/api/auth/` | 10 | OAuth 跳转与回调 |
| `delist` | `POST /api/repos/`（delist） | 5 | 与 submit 同档：改仓库状态属高危写操作；方法过滤防止被 browse 的 GET 规则吞掉 |
| `default` | 其余 `/api` | 120 | 兜底 |

以上为默认值，全部经 `config.py` 环境变量覆盖（如 `RATE_LIMIT_LLM=20`）。

**核心实现**（stdlib only）：

```python
class SlidingWindowLimiter:
    """进程内滑动窗口：键 → 窗口内命中时间戳列表。单 worker 部署下足够。"""
    def __init__(self) -> None:
        self._hits: dict[str, list[float]] = {}

    def allow(self, key: str, limit: int, window: float, now: float) -> tuple[bool, int]:
        hits = self._hits.setdefault(key, [])
        cutoff = now - window
        hits = [t for t in hits if t > cutoff]        # 剪枝即清理，无独立 GC
        if len(hits) >= limit:
            self._hits[key] = hits
            return False, max(1, int(hits[0] + window - now))
        hits.append(now)
        self._hits[key] = hits
        return True, 0
```

- 键构造：`f"u:{user_id}"`（cookie 验签通过）或 `f"ip:{client_ip}"`（`_client_ip()` 取 XFF 末段，回退 `request.client.host`）。
- 键数上限 10_000，超出时淘汰最早未命中的键，防内存膨胀（超限即拒，宁严不松）。
- `RATE_LIMIT_ENABLED` 环境变量可整体关闭（默认 true）；**测试 conftest autouse 置 false**，存量 196 个后端测试零改动。
- 中间件基于 Starlette `BaseHTTPMiddleware`（`@app.middleware("http")`），流量级无需 ASGI 原生优化。

### 4.2 中间件层序

`main.py` 中**先**挂安全中间件、**后** `add_middleware(CORSMiddleware)`：Starlette 的 `add_middleware` 是头插（`user_middleware.insert(0, ...)`），建栈时反向包裹，**列表中靠后者包成外层** —— 即后加的 CORS 成为最外层。顺序反了的话安全中间件会抢占外层，429 在到达 CORS 之前就被返回，浏览器侧读到的是 CORS 错误而不是 429 状态码。正确顺序：

```python
app.add_middleware(SecurityMiddleware)     # 先加 → 内层
app.add_middleware(                                # 后加 → 最外层，429 出来时补 CORS 头
    CORSMiddleware, allow_origins=..., allow_credentials=True, ...
)
```

### 4.3 Origin 校验（同文件）

```python
SAFE_METHODS = {"GET", "HEAD", "OPTIONS", "TRACE"}

# 非安全方法 + /api 路径：Origin 存在则必须在白名单，缺失放行
```

- 白名单复用 `config.CORS_ORIGINS`（`FRONTEND_ORIGIN` + `127.0.0.1:5173`）。
- OAuth callback 是 GET 顶层导航、无 Origin，不受影响；浏览器同源 POST 按 Fetch 规范必带 Origin 且等于站点源，命中白名单。
- 不校验 Referer（Referer 会被剥离/裁剪，不可靠；Origin 已够）。

### 4.4 nginx 安全响应头（`deploy/nginx-meecode.conf`）

server 块内新增（均带 `always`，错误响应也带头）：

```nginx
server_tokens off;
client_max_body_size 1m;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
add_header Content-Security-Policy "default-src 'self'; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; font-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'" always;
```

**`/explain-api/` location 必须同步补一行**（限流正确性的前置，非安全头）：

```nginx
location /explain-api/ {
    ...
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    ...
}
```

原因：该 location 一旦出现任何 `proxy_set_header`，nginx 编译默认的 `X-Forwarded-For` 即被清空（现配置已有 Host/X-Real-IP/Connection 三条，恰好把默认头全清了）。缺这行，全部解读域流量在后端看来同源 `127.0.0.1`，匿名 LLM 限流会退化成全局共享一桶 —— 既误伤所有用户，也让 IP 限形同虚设。

上线前已 grep 确认前端无 CDN 外链（无 googleapis/unpkg/jsdelivr）、Vite 产物无内联脚本；`index.html` 唯一内联脚本是 dev 期的 `main.tsx` 引用，构建后为外部 module 脚本。**上线验证**（写入 runbook）：`curl -sI https://<域名>/ | grep -i -E 'content-security|x-frame|strict-transport'` 逐条确认。

## 5. 测试

**新增 `backend/tests/test_security.py`**（conftest 全局关闭限流，本文件用例内 `monkeypatch` 显式开回 `RATE_LIMIT_ENABLED=True`）：
- 限流：同键第 N+1 次请求 → 429 + `Retry-After` 头 + detail；不同键互不影响；窗口推进后恢复（limiter 直接注入可控 `now`，不 sleep）；`RATE_LIMIT_ENABLED=false` 全放行；键数上限淘汰。
- Origin 校验：非安全方法 + 白名单外 Origin → 403；无 Origin → 放行（回归保护 curl/TestClient 行为）；白名单内 → 放行；GET 带恶意 Origin → 放行（GET 非状态变更）。
- IP 提取：XFF 多段取末段；无 XFF 回退 `client.host`。
- 层序：超限响应的响应头含 `access-control-allow-origin`（CORS 在外层的回归）。

**存量回归**：conftest autouse 关闭限流后，196 个后端测试 + 205 个前端用例必须全绿（限流/Origin 中间件不改变任何现有响应语义）。

**nginx**：无单测，上线验证清单写 runbook（§4.4 的 curl 逐项 + `nginx -t`）。

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| CSP 打破 README 图片/头像加载 | 上线前已 grep 无 CDN 外链；`img-src https:` 覆盖用户内容图片；回滚 = 删该 add_header 行后 reload |
| 限流误伤正常用户/分享链接的爬虫 | 浏览桶 240/min 远高于真人；只读公开端点；搜索引擎抓取频率天然低于阈值 |
| XFF 伪造导致限流键被注入 | 取 nginx 追加的末段；后端仅监听 127.0.0.1（systemd 单元），流量必经 nginx；若未来直暴露端口需重新评估取 IP 逻辑 |
| 多 worker 部署时间隔失效 | 当前单 worker；systemd 单元保持不变；扩展时换 Redis 计数（风险表记录，非本批） |
| CI 无 `.env` 导致 pytest 起不来 | test job 显式注入 `LLM_MOCK=true GITHUB_MOCK=true`（§4.5） |
| Origin 校验挡漏非浏览器客户端 | 无 Origin 头放行；挡的是「带 Origin 的跨站页面」，正是 CSRF 威胁模型 |
| nginx conf 手动 reload 被遗忘导致安全头半年不上线 | runbook 上线清单置顶 + 健康检查之外加一条 `curl -sI` 断言脚本，随 spec 交付 |
| 会话 30 天不可吊销仍是敞口 | 本批不碰；列入后续独立子项（配合管理端「踢下线」需求） |
